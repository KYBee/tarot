# 카드 상징 기반 해석 콘텐츠 설계

## 목적

결과 화면에서 카드 이미지를 본 사용자가 그림 속 요소와 해석의 연결을 별도 지식 없이 이해하게 한다. 탄생카드와 페르소나 카드를 `내 중심 → 사회에서 드러나는 모습`의 흐름으로 읽게 하고, 근거가 약한 서비스 고유 개념인 날개 카드는 제거한다.

이 콘텐츠는 타로와 수비학을 활용한 자기이해용 해석이며 심리 진단이나 미래에 대한 단정으로 표현하지 않는다.

## 범위

### 포함

- 결과 화면에서 날개 카드와 관련 계산·콘텐츠 제거
- 메이저 아르카나 0~21 전체의 Rider-Waite-Smith 이미지 상징 검토
- 카드별 `그림 속 상징` 설명 보완
- 카드별 `왜 이렇게 읽을까요?` 설명 추가
- 탄생카드와 페르소나 카드 역할에 맞는 프로필 설명 적용
- 별도 페르소나 카드가 없는 결과를 `탄생·페르소나 통합형`으로 표시
- 결과 카드의 정보 레이블과 렌더링 연결 수정
- 제품·계산·콘텐츠·UI·기술 문서와 `AGENTS.md` 동기화
- 새 콘텐츠 필드와 렌더링에 대한 회귀 테스트
- 모바일 긴 텍스트 가독성 확인

### 제외

- 탄생카드와 페르소나 카드의 기존 숫자 축약 방식 변경
- 카드 이미지 교체 또는 신규 이미지 생성
- 연도 흐름 해석 전면 개편
- 카카오 공유 기능 변경
- 프레임워크 도입이나 대규모 리팩터링

## 결과 구조

결과 스와이프는 항상 두 장을 유지한다.

1. 탄생카드: 내가 자연스럽게 돌아가는 중심 성향
2. 페르소나 카드: 사회에서 드러나는 모습

별도 페르소나 숫자가 나온 경우 두 번째 장에는 해당 페르소나 카드를 표시한다. 중간 축약 과정에서 `10~22`가 나오지 않은 경우에도 두 번째 장을 없애지 않는다. 대신 탄생카드와 같은 카드 이미지·번호·이름을 사용하고 다음 상태로 설명한다.

- 상태명: `탄생·페르소나 통합형`
- 의미: 별도의 사회적 얼굴이 없다는 뜻이 아니라, 내면의 중심과 바깥으로 드러나는 인상이 같은 카드의 결을 크게 공유한다는 뜻
- 계산 안내: `중간 축약 과정에서 별도의 두 자리 카드가 나오지 않아 탄생카드와 같은 카드로 읽습니다.`

`페르소나 카드 없음`, `페르소나가 없는 사람` 같은 표현은 사용하지 않는다.

## 카드 내부 사용자 경험

각 결과 카드는 아래 순서로 읽힌다.

1. 카드 타입과 역할 설명
2. 카드 이미지, 번호, 이름
3. 기본 의미
4. 그림 속 상징
5. 왜 이렇게 읽을까요?
6. 카드 역할에 맞는 프로필 설명
7. 계산 과정

프로필 제목은 역할에 따라 다음처럼 표시한다.

- 탄생카드: `내 중심에서 나타나는 모습`
- 페르소나 카드: `다른 사람에게 보이는 모습`

## 콘텐츠 원칙

### 그림 속 상징

- 실제 `img/`의 Rider-Waite-Smith 계열 이미지에서 확인되는 요소를 사용한다.
- 카드마다 대표 요소를 2~4개 선택한다.
- 먼저 그림에서 보이는 장면을 설명하고, 아직 성향을 단정하지 않는다.
- 이미지에 없거나 판본에 따라 불확실한 세부 묘사는 넣지 않는다.

### 왜 이렇게 읽을까요?

- 앞 문단에서 언급한 시각 요소가 어떤 의미로 연결되는지 설명한다.
- `상징 A는 의미 B를, 장면 C는 태도 D를 보여준다`처럼 연결 관계가 드러나게 쓴다.
- 카드 사전의 키워드를 반복하는 대신 사용자가 해석의 이유를 납득하게 한다.
- 카드당 2~4문장으로 제한한다.

### 역할별 프로필

- 탄생카드는 자연스럽게 돌아가는 중심 욕구, 강점, 반복 성향과 균형점을 설명한다.
- 페르소나 카드는 첫인상, 사회에서 맡기 쉬운 역할, 타인이 기대하기 쉬운 모습과 그 이미지에 갇힐 때의 부담을 설명한다.
- 통합형 페르소나는 같은 카드가 내면과 사회적 인상에서 어떻게 이어지는지 설명한다.
- 장점과 주의점을 함께 쓰되 `반드시`, `운명`, `절대` 같은 단정형 표현을 피한다.

카드별 상징 데이터는 두 역할이 공유한다. 프로필 설명은 역할별로 분리하며, 모든 카드가 통합형 페르소나로 사용되어도 안전하도록 0~21 카드에 페르소나 문구를 제공한다. 탄생 전용 문구는 계산상 탄생카드가 될 수 있는 1~9에 제공한다.

## 데이터 모델

`data/card-content.js`의 카드 객체에 다음 필드를 둔다.

```js
{
  symbolismDescription: "그림에서 직접 확인되는 장면 설명",
  symbolismInterpretation: "그 장면이 카드 의미로 이어지는 이유",
  profileDescription: "전용 문구가 없을 때 사용할 공통 성향 설명",
  roleDescriptions: {
    birth: "내 중심 성향으로 읽는 설명",
    persona: "사회적 인상으로 읽는 설명"
  }
}
```

기존 `symbolismDescription`은 `그림 속 상징`에 사용한다. 새 `symbolismInterpretation`은 `왜 이렇게 읽을까요?`에 사용한다. `profileDescription`은 이전 데이터 호환과 예외 상황을 위한 fallback으로 유지한다.

프로필 결과에는 다음 상태를 명시한다.

```js
{
  birthCard,
  personaCard,
  personaNumber,
  hasDistinctPersona
}
```

- 별도 페르소나가 있으면 `personaCard`는 해당 카드이고 `hasDistinctPersona`는 `true`다.
- 별도 페르소나가 없으면 기존 계산 결과인 `personaNumber: null`은 유지하고, `personaCard`는 `birthCard`, `hasDistinctPersona`는 `false`다.
- 날개 카드 번호와 카드 데이터는 프로필 결과에서 제거한다.

## 화면 및 렌더링 변경

- `index.html`에서 날개 카드 슬라이드와 세 번째 도트를 제거한다.
- 탄생·페르소나 카드 정보 상자에 `왜 이렇게 읽을까요?` DOM 영역을 추가한다.
- 각 카드의 프로필 제목을 역할별 문구로 변경한다.
- `script.js`의 공통 카드 렌더러가 `symbolismInterpretation`과 현재 역할의 `roleDescriptions` 문구를 표시한다.
- 통합형은 탄생카드의 이미지와 콘텐츠를 페르소나 역할 문구로 렌더링하고, 별도 상태명과 계산 안내를 표시한다.
- 스와이프 도트와 접근성 레이블은 두 장 기준으로 갱신한다.
- 새 문단은 기존 본문 스타일을 재사용하고 필요한 최소 간격만 `style.css`에 추가한다.

## 자료 검증

- A. E. Waite의 *The Pictorial Key to the Tarot*를 기본 원전으로 삼는다.
- Pamela Colman Smith의 실제 카드 이미지와 원전 설명을 함께 확인한다.
- 현대 해설은 상징과 성향의 연결을 이해하기 위한 보조 자료로만 사용한다.
- 자료마다 해석이 다른 경우 널리 공유되는 의미만 쓰거나 단정하지 않는 표현으로 조정한다.
- 생년월일 카드 계산법과 역할 명칭은 단일한 전통 표준이라고 주장하지 않고 서비스의 해석 체계로 소개한다.

## 예외 및 실패 처리

- 카드에 `symbolismInterpretation`이 누락되더라도 기존 상징·프로필 설명은 계속 렌더링한다.
- 역할별 설명이 누락되면 기존 `profileDescription`을 사용해 결과 화면이 깨지지 않게 한다.
- 카드 이미지가 로드되지 않아도 텍스트만으로 상징과 해석을 이해할 수 있어야 한다.
- 콘텐츠가 길어져도 카드 높이를 고정하지 않고 세로 스크롤로 전체 내용을 읽을 수 있게 한다.

## 검증

자동 검증:

- 날개 카드 계산·렌더링·DOM 참조가 남아 있지 않은지 검사
- 0~21 모든 카드에 비어 있지 않은 `symbolismInterpretation`과 페르소나 설명이 있는지 검사
- 1~9 모든 카드에 비어 있지 않은 탄생 설명이 있는지 검사
- 별도 페르소나가 있는 결과와 통합형 결과를 각각 검사
- 통합형에서 `personaNumber`는 `null`, `personaCard`는 탄생카드와 동일한지 검사
- 기존 탄생·페르소나·연도 계산과 이미지 매핑 회귀 테스트 유지
- `node --test tests/script.test.js`
- `node --check script.js`
- `node --check data/card-content.js`

브라우저 검증:

- 360px 모바일에서 입력부터 결과까지 확인
- 탄생·페르소나 카드의 역할별 레이블 차이 확인
- 긴 상징 설명에서 카드 레이아웃과 행간 확인
- 별도 페르소나가 있는 날짜와 통합형 날짜를 각각 확인
- 두 장 스와이프, 다시 하기, 공유 fallback 흐름이 유지되는지 확인

## 완료 기준

- 결과 화면에 날개 카드 개념이 남아 있지 않다.
- 통합형 사용자가 `페르소나가 없는 사람`으로 오해되지 않는다.
- 사용자가 카드 이미지를 보면서 주요 상징을 실제로 찾을 수 있다.
- 그림의 요소와 해석 사이의 연결이 한 문단 안에서 이해된다.
- 탄생과 페르소나가 각각 중심과 사회적 얼굴로 구분되어 읽힌다.
- 문서와 런타임 콘텐츠가 같은 정책과 내용을 가진다.
- 기존 탄생·페르소나·연도 계산, 스와이프, 공유 fallback이 깨지지 않는다.
