# 프로필 관계 UI와 카드 콘텐츠 V2 설계

## 1. 목적

결과 화면의 탄생카드와 페르소나카드를 독립된 두 결과가 아니라 `내 중심 → 사회에서 보이는 나`로 이어지는 하나의 프로필로 읽히게 한다. 동시에 메이저 아르카나 22장의 설명을 성향, 강점, 그림자, 관계, 일, 성장 포인트 중심의 카드 콘텐츠 V2로 교체한다.

점괘처럼 미래나 삶의 결과를 단정하지 않는다. 사용자가 자신의 성향을 이해하고 균형점을 찾도록 돕는 현재 서비스 톤을 유지한다.

## 2. 범위

### 포함

- 기존 결과 화면의 2장 스와이프 구조 유지
- 스와이프 단계 표시를 `내 중심`과 `보이는 나`로 개선
- 페르소나 슬라이드 상단에 두 카드의 관계를 설명하는 패널 추가
- 통합형과 분리형에 서로 다른 관계 문구 제공
- 사용자가 제공한 메이저 아르카나 22장 콘텐츠 V2 반영
- 탄생카드 기준 상세 프로필 아코디언 추가
- 관련 콘텐츠·UI 문서와 회귀 테스트 동기화
- 320px, 360px, 430px 모바일 QA

### 제외

- 계산 규칙 변경
- 세 번째 결과 슬라이드 또는 중간 연결 슬라이드 추가
- 카드 조합별 22×22 전용 해석 작성
- 프레임워크 도입이나 대규모 구조 변경
- 연도 흐름의 레이아웃 재설계

## 3. 사용자 경험 흐름

### 3.1 첫 번째 슬라이드: 내 중심

탄생카드는 사용자의 타고난 중심 성향을 설명한다. 다음 순서로 핵심 정보를 노출한다.

1. `나의 탄생카드` 제목과 타입 설명
2. 카드 이미지, 번호, 이름
3. 한 줄 정체성
4. 기본 의미
5. `그래서 어떤 사람인가`
6. 탄생카드 역할 설명
7. 그림 속 상징과 `왜 이렇게 읽을까요?`
8. 계산 과정

첫 장에서는 페르소나 유형을 미리 공개하지 않는다. 사용자가 먼저 자신의 중심을 읽은 뒤 옆으로 넘겨 관계를 발견하게 한다.

### 3.2 두 번째 슬라이드: 보이는 나

두 번째 슬라이드는 단순한 페르소나 카드 소개가 아니라 탄생카드와 페르소나카드의 관계를 설명하는 장이다.

1. `페르소나 카드` 제목과 타입 설명
2. 관계 유형 배지
3. `탄생카드 → 페르소나카드` 연결 표시
4. 관계 설명
5. 페르소나 카드 이미지, 번호, 이름
6. 페르소나 역할 설명
7. 그림 속 상징과 `왜 이렇게 읽을까요?`
8. 계산 과정

분리형에서는 페르소나 카드의 한 줄 정체성과 상징 설명을 제공한다. 통합형에서는 첫 장의 `그래서 어떤 사람인가`를 반복하지 않고, 같은 성향이 사회적 인상으로 어떻게 이어지는지에 집중한다.

### 3.3 상세 프로필

스와이프 카드 아래, 연도별 흐름 위에 `나의 프로필 더 보기` 영역을 둔다. 상세 프로필은 중심 성향을 확장하는 정보이므로 탄생카드 데이터를 기준으로 한다.

- `강점과 그림자`: `strengthDescription`, `shadowDescription`
- `관계와 일`: `relationshipDescription`, `workStyleDescription`
- `성장 포인트`: `growthPointDescription`

각 항목은 기본 `<details>`와 `<summary>`를 사용한다. 초기 상태는 접힘이며 사용자가 원하는 정보만 세로로 펼쳐 읽을 수 있다.

## 4. 통합형과 분리형 표현

### 4.1 통합형

- 배지: `같은 카드, 같은 방향`
- 연결 표시: `{탄생카드} → {같은 카드}`
- 관계 문구: `내면과 사회적 인상 모두 “{한 줄 정체성}”이라는 같은 방향으로 이어져요.`

통합형은 가면이 없거나 단순하다는 뜻으로 설명하지 않는다. 내면의 가치와 외부 표현이 비교적 한 방향으로 이어지는 유형으로 설명한다.

### 4.2 분리형

- 배지: `내 중심이 다른 모습으로 표현돼요`
- 연결 표시: `{탄생카드} → {페르소나카드}`
- 관계 문구: `내면에서는 “{탄생카드 한 줄 정체성}”의 성향이 중심을 이루고, 사람들에게는 “{페르소나카드 한 줄 정체성}”의 모습이 먼저 보일 수 있어요.`

분리형은 이중적이거나 모순적이라는 뜻으로 설명하지 않는다. 내면의 힘이 사회와 관계 맺는 과정에서 다른 방식으로 표현되는 유형으로 설명한다.

## 5. 내비게이션과 시각 표현

- 기존 두 개의 점을 `내 중심`, `보이는 나`가 적힌 두 단계 표시로 교체한다.
- 현재 단계는 골드 색상과 명확한 상태 차이로 표시한다.
- 단계 표시는 스와이프 위치와 동기화한다.
- 페르소나 슬라이드가 활성화되면 관계 패널이 짧게 나타난다.
- 관계 패널은 딥 퍼플 글래스 배경과 골드 연결선을 사용해 현재 우주적 카드형 디자인을 유지한다.
- 통합형과 분리형을 서로 다른 강한 색으로 나누지 않는다. 유형의 우열이나 충돌로 읽히지 않게 한다.
- `prefers-reduced-motion: reduce`에서는 관계 패널 등장 모션을 제거한다.
- 단계 표시는 보조 기술에서도 `내 중심 1/2`, `보이는 나 2/2`로 이해할 수 있어야 한다.

## 6. 콘텐츠 데이터 모델

기존 카드 필드는 유지하고 아래 필드를 추가한다.

```js
{
  tagline: "한 줄 정체성",
  strengthDescription: "강점",
  shadowDescription: "그림자",
  relationshipDescription: "관계에서의 모습",
  workStyleDescription: "일과 성취 방식",
  growthPointDescription: "성장 포인트"
}
```

기존 필드는 콘텐츠 V2 원문에 맞게 교체한다.

- `keywords`: 기본 의미
- `profileDescription`: 그래서 어떤 사람인가
- `symbolismDescription`: 그림 속 상징
- `symbolismInterpretation`: 왜 이렇게 읽을까요?
- `roleDescriptions.birth`: 탄생카드
- `roleDescriptions.persona`: 페르소나
- `yearFlowDescription`: 연도 카드

메이저 아르카나 0~21 모두 새 필드를 가진다. 현재 계산 규칙상 탄생카드는 1~9만 나오지만, 콘텐츠의 완결성과 향후 재사용을 위해 모든 카드에 `roleDescriptions.birth`를 보관한다.

## 7. 렌더링 구조

`buildTarotProfile`과 계산 규칙은 바꾸지 않는다. 렌더링 단계에서 다음 정보를 조합한다.

- `renderBirthCardSection`: 탄생카드 핵심 콘텐츠와 V2 문구
- `renderPersonaCardSection`: 통합형·분리형 관계 패널과 페르소나 콘텐츠
- 관계 카피 생성 순수 함수: `hasDistinctPersona`, 탄생카드, 페르소나카드를 받아 배지·연결 레이블·설명을 반환
- 상세 프로필 렌더러: 탄생카드의 강점·그림자·관계·일·성장 데이터를 각 아코디언에 연결

새 필드가 누락되면 빈 문자열을 노출하지 않고 기존 `profileDescription` 또는 역할별 설명으로 대체한다. 한 카드의 선택 필드 누락이 전체 결과 렌더링을 막아서는 안 된다.

## 8. 콘텐츠 원칙

- 사용자가 제공한 카드 콘텐츠 V2를 기준 원문으로 사용한다.
- 건강, 질병, 금전, 결혼, 특정 직업이나 사건을 예언하지 않는다.
- 강점과 그림자를 함께 보여주되 낙인처럼 단정하지 않는다.
- `~할 수 있습니다`, `~하기 쉽습니다`, `~이 중요합니다`처럼 가능성과 방향을 설명한다.
- 통합형을 `가면이 없음`, 분리형을 `이중적임`으로 표현하지 않는다.
- 카드 이름과 표기는 기존 canonical 번호 정책을 따른다.

## 9. 접근성과 반응형

- 아코디언은 기본 `<details>` 요소로 키보드 접근성을 확보한다.
- 단계 표시는 텍스트 레이블과 현재 상태를 함께 제공한다.
- 긴 본문은 기존 본문보다 충분한 행간을 유지한다.
- 320px에서도 관계 연결 표시와 카드 이름이 줄바꿈으로 깨지지 않게 한다.
- 상세 영역을 모두 펼쳐도 가로 스크롤이 생기지 않아야 한다.
- 애니메이션은 정보 이해에 필수적이지 않으며 모션 감소 설정을 따른다.

## 10. 테스트와 검증

### 자동화 테스트

- 0~21 모든 카드에 V2 필드가 존재하고 비어 있지 않은지 검사
- 통합형 관계 카피와 연결 레이블 검사
- 분리형 관계 카피와 연결 레이블 검사
- 상세 프로필이 탄생카드 데이터를 사용하는지 검사
- 통합형 페르소나 슬라이드가 전체 성향 본문을 중복 렌더링하지 않는지 검사
- 결과 마크업이 두 슬라이드와 두 단계 표시를 유지하는지 검사
- 기존 계산, 이미지 매핑, 공유 fallback 회귀 테스트 유지

### 브라우저 QA

- 320px, 360px, 430px에서 가로 넘침 확인
- 통합형과 분리형 결과 확인
- 스와이프와 단계 표시 동기화 확인
- 모든 아코디언의 펼침·접힘과 키보드 조작 확인
- 긴 콘텐츠를 모두 펼친 상태의 가독성과 하단 연도 흐름 연결 확인
- 다시 하기와 공유 fallback 회귀 확인
